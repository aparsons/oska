# Compliance

How Oska measures up against common standards, written by the Oska project. Each report is a **self-assessment**: the Oska project judges itself and cites a pinned commit or release for each claim. No third party performed or certified it. Read [how these reports are written](template.md) for the rating scale and what a determination means, and the [Compliance FAQ](faq.md) for what the repository can prove about its license, SBOM, signatures, provenance and vulnerability reporting.

## The ten standards

Each standard gets one report, redone at each minor release; the new set replaces the old one, and git keeps the history. A report gives its **determination** (Conforms, Partially conforms or Does not conform) beside the standard's own measure. The determinations are to come: the reports are written against v0.5.0 and its commit, after that release ships.

| Standard | The standard's own measure | Determination |
|---|---|---|
| Apache License 2.0 | License terms met (sections 4 and 5) | To come |
| NIST SP 800-218, Secure Software Development Framework (SSDF) | Practices met | To come |
| OpenSSF Open Source Project Security Baseline (OSPS) | Baseline level | To come |
| SLSA, Supply-chain Levels for Software Artifacts | Build level | To come |
| SPDX, Software Package Data Exchange | Requirements met | To come |
| ISO/IEC 25010, Software Product Quality | None: observations only, no determination | None |
| NIST Cybersecurity Framework 2.0 | Implementation Tier per Function | To come |
| OpenSSF Scorecard | Score | To come |
| ISO/IEC 5230, OpenChain License Compliance | Requirements met | To come |
| ISO/IEC 18974, OpenChain Security Assurance | Requirements met | To come |

ISO/IEC 25010 defines no pass criteria, so its report gives observations mapped to the standard's quality characteristics and no determination. NIST CSF 2.0 is judged by its Implementation Tiers, and its determination follows the lowest Tier.
