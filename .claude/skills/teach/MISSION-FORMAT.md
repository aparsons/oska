# MISSION.md format

Read this file when you write or change `MISSION.md`.

The mission says why the user wants to learn the topic. Each lesson serves it.

## Rules

- One mission for each workspace. For a second goal, use a second workspace.
- Make it concrete. "Bake an open-crumb sourdough loaf on a weekday" is concrete. "Get better at bread" is not.
- Keep it short. The whole file fits on one screen.
- Change it when the goal of the user changes. Confirm the change with the user first, and write a learning record about it.

## Sections

1. **Why**: the real reason, in the user's words if possible.
2. **Success criteria**: how the user will know that they got there. Each criterion is something that a person can see or test.
3. **Constraints**: time, money, tools, and other limits.
4. **Out of scope**: what the user does not want to learn now.

## Example

```markdown
# Mission: weekday sourdough

## Why

I want to bake bread for my family each week without a bakery trip.
Shop bread has too many additives for my taste.

## Success criteria

- I bake a loaf with an open crumb and a dark crust, three weeks in a row.
- I keep my starter alive and active without a written schedule.
- I can fix a dense loaf by finding the cause myself.

## Constraints

- About 30 minutes of hands-on time on a weekday.
- A home oven and one cast-iron pot. No proofing box.

## Out of scope

- Enriched doughs (brioche, sweet buns).
- Selling bread.
```
